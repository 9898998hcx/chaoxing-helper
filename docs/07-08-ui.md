# Step 7–8：模板联动与前后端 UI

## 实际页面与流程

| 页面 | 用途与主要行为 |
| --- | --- |
| `/` | 产品入口与原创简历示意，提供“开始写简历”和“看看简历结构”入口 |
| `/register`、`/login` | 邮箱注册登录、密码显示切换、请求加载状态、服务端错误提示；成功后进入简历列表 |
| `/verify-email?token=...` | 用户主动确认验证；令牌不存入浏览器本地存储；失效时引导登录后重发 |
| `/resumes` | 简历列表、创建、复制、删除确认、空状态、邮箱验证重发入口 |
| `/resumes/new?templateId=...` | 跳转到新建简历表单，保留所选结构标识 |
| `/resumes/:id` | 八模块表单、即时预览、自动保存、排序和显隐、AI 助手、快照/恢复、PDF 样式与下载 |
| `/templates` | 风格、标签、行业筛选；岗位、行业、经历关键词的规则推荐 |
| `/templates/:id` | 模块顺序、风格、标签、授权与来源链接；“使用此结构生成”入口 |
| `/admin` | 管理员专用模板审核、来源配置、任务查看和操作记录 |

主流程：注册/登录 → 新建简历 → 编辑与自动保存 → AI 生成预览 → 明确采纳或放弃 → 选择 PDF 样式 → 下载。

模板流程：结构参考 → 筛选或规则推荐 → 详情 → 选择新建或已有简历 → 应用模块顺序与模板 ID → 打开 AI 助手 → 预览生成结果 → 用户采纳后自动保存。

登录 Cookie 由 API 设置为 HttpOnly。前端在内存中持有 CSRF Token，写请求通过 `x-csrf-token` 发送；刷新后重新获取会话。前端不包含 DeepSeek API Key，不将简历、密码或会话写入 localStorage。

## 模板参考的边界

推荐接口为 `/api/templates/recommendations`，依靠标签匹配、行业匹配与简单集合相似度排序，无需 AI Key。无有效匹配时返回通用结构，并明确提示降级；模板为空时仍可直接新建普通简历。

新建时从模板取得 `sectionOrder`，对共享模块默认值排序，再提交 `sections` 和 `templateId`。对已有简历应用时先读取最新修订号，调整原有模块顺序并设置 `templateId`，保留用户正文。所有写入仍受后端权限与修订号检查。

详情页显示原创示意排版，不使用第三方完整图片模拟模板。第三方来源链接在新窗口打开，只允许 HTTP/HTTPS URL。模板原文、完整图片和模板源文件不会从前端传入模型。AI 服务根据模板 ID 在服务端提取允许的结构与风格约束。

## 编辑、保存与冲突

- 表单编辑后约 800ms 自动保存；同一编辑器中的请求串行发送，写入携带最新 `revision`。
- 保存中继续输入会保留最新输入，前一次响应只更新修订号与保存时间，不会用旧快照覆盖新内容。
- AI 请求、PDF 下载、手动快照和恢复历史版本前先完成待保存修改。保存失败时中止这些动作。
- 发生 409 版本冲突时停止自动重试，保留页面草稿，允许下载 JSON 草稿备份；重新载入需明确确认，避免静默覆盖。
- 存在待保存修改时，刷新或关闭窗口触发浏览器离开提醒；点击编辑器“我的简历”返回按钮时先保存。
- 删除简历与恢复历史版本使用确认对话框；删除会连同历史版本移除。后台下架要求填写审核原因并再次确认。

## AI 预览与采纳

助手支持模块生成、已有内容润色、自我评价、改进建议。界面显示今日剩余额度、模型配置状态、加载、错误和重试入口。生成响应只显示在独立预览区域，不向简历 PATCH 接口写入。

“采纳到某模块”是唯一写入入口：用户点击后替换对应模块的编辑器内容，随后按正常自动保存机制持久化，内容仍可修改。“放弃此结果”只清除生成预览；改进建议仅展示，不直接替换正文。AI 输出使用 React 文本渲染，不作为 HTML 执行。

## 响应式与可访问性

桌面使用左表单、右纸张预览；手机使用“编辑内容 / 实时预览”切换，保留 AI、版本和 PDF 入口。没有依赖远程字体；系统中文字体用于界面，服务器 PDF 使用部署配置指定的中文字体。

界面包含跳转到主要内容链接、输入标签、键盘可见焦点、Tab 状态、状态播报与错误提示。登录表单支持浏览器自动填充；密码显示按钮独立于输入标签。列表与后台表格支持窄屏，采集任务与审计表格可横向滚动。尊重减少动态效果设置。

预览中的空模块文案仅用于辅助填写；导出 PDF 会省略空条目。实际 PDF 分页以服务端生成文件为准。

## 手动验收步骤

1. 启动本地服务，在 `/register` 创建账户；退出后重新登录，刷新确认会话仍有效。使用错误密码确认显示明确错误。
2. 新建简历，填写姓名、求职方向、工作成果。等到“所有修改已保存”，刷新确认内容恢复。复制简历，核对副本与原件独立。
3. 调整工作和教育模块顺序，隐藏证书，刷新核对持久化；增加、移除一条项目经历并查看预览。
4. 同账户在两个页面打开同一简历。A 保存后再修改 B，确认 B 显示冲突且保留输入；下载草稿后确认重新载入。
5. 保存快照，再修改自我评价；从历史版本恢复旧版本，确认有二次确认且形成新版本。
6. 无 Key 时请求 AI，确认配置错误不会写入简历。有可用服务或测试拦截时，生成自我评价，采纳前刷新另一个页面核对原文未变；放弃不变，采纳后保存且可继续编辑。
7. 在模板库按岗位与行业推荐，确认无需 AI。打开详情选择新建或已有简历，确认仅顺序和关联模板变化，原正文保留；生成内容仍需采纳。
8. 选择三种 PDF 样式之一并下载，检查中文、长描述分页、文件名；手机切换预览后同样可触发下载。
9. 普通用户访问 `/admin` 应无权限。管理员新增来源默认禁用；无授权依据启用失败。对待审核模板填写原因后通过，公开库可见；下架后公开详情不可用。
10. 在 390px 和桌面宽度检查登录、列表、编辑、模板与后台；使用键盘完成登录、打开模块与敏感操作确认，检查焦点和错误提示。

自动化入口：`npm run test:e2e`。桌面与手机主流程测试覆盖注册、保存与刷新恢复、排序、AI 预览/采纳边界、下载和删除；真实 API 的越权、审核与采集策略由后端集成测试覆盖。真实 DeepSeek 成功请求需用户配置有效 Key，自动化使用结构化响应拦截验证交互边界。
