# Step 4：DeepSeek 辅助生成

后端已提供按模块生成、润色、自我评价与改进建议。生成结果只返回给 AI 面板预览，由用户点击采纳后通过正常简历保存接口写入；生成接口本身不修改简历。

## 接口

- `GET /api/ai/quota`：登录后查询 `configured、remaining、dailyLimit、resetAt、budgetWarning、monthlyReservedTokens、monthlyTokenLimit`。
- `POST /api/ai/generate`：登录、来源与 CSRF 校验；请求 `resumeId、scenario、sectionType?、jd?、experience?、content?、templateId?`；场景为 `generate-section / polish / summary / suggestions`。
- 响应：`generationId、scenario、result:{sectionType,items,suggestions}、quota:{remaining,dailyLimit,budgetWarning}`。`items` 为目标模块允许字段构成的字符串对象数组。
- 错误统一为 `{error:{code,message}}`。缺 Key 为 `503 AI_NOT_CONFIGURED`；无权限为 `404 RESUME_NOT_FOUND`；超时为 `504 AI_TIMEOUT`；本地限流为 `429 RATE_LIMITED`；日额度为 `429 AI_DAILY_LIMIT`；月预算为 `429 AI_MONTHLY_BUDGET`；结构错误为 `502 AI_INVALID_OUTPUT`。上游错误正文不会返回用户。

## 配置

使用根目录 `.env.example` 的 `DEEPSEEK_API_KEY、DEEPSEEK_BASE_URL、DEEPSEEK_MODEL、DEEPSEEK_TIMEOUT_MS、DEEPSEEK_MAX_RETRIES、DEEPSEEK_MAX_OUTPUT_TOKENS、AI_DAILY_LIMIT、AI_REQUESTS_PER_MINUTE、AI_MONTHLY_TOKEN_LIMIT、AI_BUDGET_WARNING_PERCENT`。Key 仅后端读取，禁止放入 `NEXT_PUBLIC_*`。

默认模型可配置，默认调用 `https://api.deepseek.com/chat/completions`。使用 DeepSeek JSON 模式 `response_format:{type:'json_object'}`，提示词包含 JSON Schema，服务端再以 Zod 校验类型、目标模块、允许字段和大小。此实现不宣称提供方支持严格 `json_schema` 模式。

每次请求最长等待默认 20 秒，最多重试 2 次，仅对超时、网络错误、429 与 5xx 重试。重试使用有限退避。响应读取受 256 KiB 上限保护。只发送用户选择的模块内容与用户主动填写的 JD/经历；不会自动发送简历中的其他联系信息模块。模型被明确要求不编造用户事实。

## 额度与脱敏

每用户默认每分钟 5 次、每日 20 次；UTC 零点重置日额度。分钟限流本地使用内存，生产多实例需要真实 Redis。日额度与全站月 token 预算通过数据库 SERIALIZABLE 事务先建立 PENDING 日志预留，再发出网络请求；数据库冲突有限重试，失败时拒绝请求。进程重启不会清空预留额度。

预留值为 `(请求 UTF-8 字节数 + 单次最大输出 token) × 最大尝试次数`。该值保守计算所有可能重试，完成后仍保留，因此预算额度会早于提供方实际账单耗尽。日志另记提供方返回的实际输入/输出 token。超时或进程中断不能证明提供方未计费，故不释放未知预留；需人工核对再调整下月预算。这个机制限制 token 估算，不是按人民币计价的账单封顶，仍应在 DeepSeek 控制台设置预算告警。达到默认 80% 返回 `budgetWarning`。

日志仅包含用户/简历/模板 ID、场景、状态、token、耗时及错误码；不记录提示词、JD、经历、简历正文、上游正文、Key。无 Key 的失败记零预留日志，不消耗日额度，但仍受分钟限流保护，防止失败请求无限写入日志。模板只查询已审核条目，并将 `sectionOrder、layout、style` 注入提示词；不查询或注入来源正文、标题、描述或图片。

## 验收

1. 清空 Key，登录后发起生成：返回明确 503，面板可重试；数据库仅出现脱敏失败日志、零预留。
2. 配置有效 Key：选择已有简历模块，输入 JD/经历，预览返回内容；放弃时简历保持原内容，采纳后可继续编辑，刷新后保存内容存在。
3. 模拟超时和 429：最多执行配置次数的重试；最终失败有明确消息。以另一账号请求目标简历 ID 返回 404，且不调用提供方。
4. 降低日/月额度：超过限额返回 429；重启 API 后额度仍有效。生产用两个实例验证共享 Redis 分钟限流与数据库预算冲突处理。
5. 选择第三方结构模板：检查发出的消息仅有模块顺序、布局与风格；来源正文/缩略图不得出现；下架模板显式选择返回 404，已保存简历的失效模板自动降级为无参考。
6. 检查 `AiGenerationLog`：没有完整敏感简历、JD、提示词、响应正文或 Key。用 `npx vitest run apps/api/src/ai/ai.service.test.ts` 执行自动化失败路径与脱敏检查。

真实 DeepSeek 计费调用需使用部署方提供的 Key 验证；本地自动化使用受控 Fetch 响应，不消耗付费额度。
